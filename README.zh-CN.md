# TaskQuay

**任务看得见，执行有回执。**

[English](README.md) · [简体中文](README.zh-CN.md) · [GitHub](https://github.com/wrfgup/taskquay) · [安全边界](docs/security.md) · [MIT 许可证](LICENSE)

TaskQuay 是一个自托管的 MCP 本地执行与项目任务管理工具。让 ChatGPT 等主控直接查看工作区，在确有必要时调度 Codex，以可检查的变更、测试证据和用量回执完成一项任务。

本项目是 **[Waishnav/DevSpace](https://github.com/Waishnav/devspace) 的独立二开分支**，不是 OpenAI、Anthropic 或上游 DevSpace 的官方产品。我们保留上游实现和 MIT 版权声明，主要改进主控直读、有界并行、会话复用、任务可观测性与 Codex 用量统计。

> **早期项目，优先从本分支源码运行。** 对外名称为 TaskQuay；为保持兼容，CLI、配置目录、MCP 标识及现有界面中的 `devspace` 名称暂不变。源码仓库为 [wrfgup/taskquay](https://github.com/wrfgup/taskquay)。上游 npm 包不等于本分支，当前不宣称已有 TaskQuay npm 发行包。

## 为什么做这个分支？

让模型执行一条终端命令，只解决了远程开发的一小部分问题。真正长程使用时，还需要知道：任务是谁下发的？是否还有人在写文件或编译？哪个会话已经了解这个问题？验收完成了吗？本次究竟用了多少 Codex Token？

TaskQuay 把这些信息变成明确的工具能力与本地记录，而不是全部依赖聊天上下文去记忆。

| 能力 | 解决什么问题 |
| --- | --- |
| **主控先读** | 主控使用 `read`、`workspace_context` 读取指定文件、搜索文本、提取版本化引用，不必先启动 Codex 理解整个项目。 |
| **受控委派** | 经过权限确认的只读代理可以限量并行；写入及未知副作用命令保持独占，共享编译输出和设备单独声明资源占用。 |
| **合理复用会话** | 相关工作继续已有线程；工作目标、上下文亲和与请求幂等分别管理，独立审查可以明确使用新上下文。 |
| **项目任务台** | `/console/` 按项目展示任务来源、执行状态、验收证据、Codex 会话、用量及待核对占用。 |
| **用量回执** | 完成工作时返回 provider 实际报告的用量和完整性；缺少统计事件不能直接当成零。 |
| **项目级聊天整理** | 归档／恢复先预览准确范围，再确认执行；无法核实归属或活动状态的会话跳过。 |

目标是减少不必要的新上下文、重复调查和竞争返工，不是让尽可能多的代理同时工作。项目不承诺固定比例的 Token 节省。

## 工作方式

```text
你
  └─ MCP 主控：规划、直接读取、关键判断、验收
       └─ TaskQuay / 兼容的 devspace 工具
            ├─ 工作区读取、修改、命令与证据
            ├─ 任务账本、并发与资源协调
            ├─ 确有需要才调用的 Codex 会话
            └─ 项目任务台与完成回执
```

主控仍然负责统筹。TaskQuay 不是不可检查的自主总管，也不是 Codex 的替代品或模型服务。

**本地执行不等于数据永不离开电脑。** 经 MCP 返回的文件内容会进入你选择的主控；委派给 Codex 的输入和工具结果也可能发送给模型提供方。请只连接获准处理的项目，并核对所使用服务的当前隐私设置与条款。

## 从本分支源码运行

环境要求以 `package.json` 为准：Node.js `>=22.19 <27`、Git，以及固定版本 `pnpm@11.25.0`。需要 Codex 委派时，另行安装并登录兼容的 Codex CLI；主控直接读取工作区不需要发起 Codex 推理。

先克隆**本二开分支**，再按以下步骤运行：

当前 `package.json` 设置了 `private: true`，防止误用上游包名发布 npm 包；这不妨碍将审查后的源码仓库按 MIT 开源。

```sh
git clone https://github.com/wrfgup/taskquay.git
cd taskquay
npm install --global pnpm@11.25.0
pnpm install --frozen-lockfile
pnpm build
node bin/devspace.js init
node bin/devspace.js doctor
node bin/devspace.js serve
```

按初始化向导选择授权根目录、provider 和连接配置。妥善保管生成的 owner 授权口令。已有安装应先备份配置与状态，在隔离环境验证，避免互相覆盖。

**不要在服务执行任务时直接清理或重建它的 `dist`。** `pnpm build` 会替换构建产物；升级应等活动任务结束，再受控停止、构建、重启，并刷新主控工具列表。

### 连接 MCP 主控

默认本机 MCP 地址：

```text
http://127.0.0.1:7676/mcp
```

云端主控通常需要可访问的 HTTPS 入口，例如：

```text
https://your-controlled-host.example/mcp
```

初始化时填写不含 `/mcp` 的站点根地址，自己配置并管理隧道或反向代理，再完成 owner 授权。TaskQuay 不接管你的隧道。

同一个 `/mcp` 入口保留上游的 2026-07-28 逐请求协议支持，并通过无状态兼容处理较早的 2025 版客户端，无需另选协议模式。

自定义 MCP 能力是否可用，取决于主控产品、账号、工作区设置及策略。接入 ChatGPT 前请查看[当前官方说明](https://help.openai.com/en/articles/12584461-developer-mode-and-mcp-apps-in-chatgpt)。本项目不提供产品权限，也不绕过提供方限制。

### 打开项目任务台

```text
http://127.0.0.1:7676/console/
```

任务台使用 owner 口令建立独立浏览器会话，默认仅本机访问。开放 `/mcp` 不会自动开放远程管理台；远程管理需要单独明确开启 HTTPS 入口。详见[任务台说明](docs/project-console.md)和[配置参考](docs/configuration.md)。

## 推荐的任务闭环

主控先用 `work_task` 建立本次工作，再将 `workRunId` 传递给读取、修改、命令和代理调用。先直接收集相关上下文，只有确实适合委派时才启动 Codex，并提供清楚的范围、版本化证据和验收标准。后续修正与测试优先继续相关会话。

需要独立审查时保留独立视角。等子操作真正结束、主控检查过实际验收证据后，再结算任务。模型说“完成了”，不等于构建、部署或 GUI 验证真的成功。

可以这样向已经连接的主控下达任务：

> 打开已授权的项目，建立工作记录。先直接阅读相关实现，提出最小安全修改。确有需要再调用 Codex，相关后续复用同一会话。执行适当检查、审查最终 diff，并返回本次 Codex 用量与统计完整性。不要未经单独授权部署或公开发布。

工具约定和并行细节见[主控直读工作流](docs/host-first-readonly-workflows.md)。

## 怎么看 Token 数字

| 状态 | 含义 |
| --- | --- |
| **完整** | 受管执行边界及 provider 用量事件齐全。 |
| **部分** | 有已记录用量，但任务仍存在统计缺口。 |
| **未知** | 证据不足，不能给出准确数字；不是零。 |
| **未调用** | 对应工作没有启动受管 Codex 推理。 |

缓存输入和推理输出属于明细，不能再加到总量上。历史会话用量、手工在 Codex 中继续的活动，以及其他外部模型命令，不能仅因工作目录相同就算到本次任务。Token 记录不等于订阅余额或账单；会话复用也不保证缓存命中。

运行时池回调修复及回归范围见[用量统计说明](docs/console-usage-callback-fix.md)。旧记录没有可靠证据时应保持未知，而不是补造历史数据。

## 安全边界与当前限制

**请把连接视为高权限本地访问。** 文件工具执行工作区路径校验，但 shell 命令使用本机用户权限，不是通用文件系统沙箱。源码锁、资源锁只能协调接入同一机制的操作，不能阻止外部编辑器或终端。

只读分析不包括构建、安装依赖、写数据库、操作设备或发布；这些操作应申请对应执行权限和资源。中断后的占用需要核对，归档聊天不是取消进程。

本分支主要在 Windows 上开发并进行本地验证，保留上游跨平台代码和 CI 定义。CI 中列出了平台，不等于当前二开的每项功能都已经在这些平台实际通过；请验证自己的主控、provider 与系统组合。继承的原生附件下载也存在平台限制。

本项目不宣称已经实现自动不可变快照、任意历史节点分叉、保证缓存关联或完整自动僵尸任务恢复。归档／恢复有安全夹具测试，但已有“零推理空线程”实测没有完成真实恢复与清单验证。使用批量归档前，先在自己的 Codex 实例中用明确授权的新测试会话验证，不要拿无关聊天做实验。

请勿将 owner 口令、provider 凭据、私人会话文件、任务数据库、个人路径或未经脱敏的截图发到公开 Issue。发布前检查见[开源清单](docs/open-source-checklist.md)。
